# 实验方案可行性评估

## 触发与职责

在审查具体版本实验方案能否按本案条件开工，或用户要求资源核验、七类约束检查、条件性可行结论时触发。重点是“具体版本的具体位置→证据→判定→行动”，不是重写方案或堆砌通用建议。不做实验执行、文献综述、论文写作或统计分析；不伪造审批、库存、报价、档期、日志或实验结果。

## 案件与合同

1. 完整读取`/input/case.json`、`/input/task.md`及case指向的方案全文、附件、SOP、设备/材料清单、采购与预约资料、伦理安全文件和真实科学来源。PDF按实际文件解析，不依赖预抽取答案。
2. 逐项读取真实`case.output_contract`；最终`/app/output/result.json`含真实`case_id`和合同所有原字段/层级/类型/artifact。本技能的七域语义不得直接捏造成未公开JSON键。
3. 在`/app/work`建立来源索引：`方案ID+版本→章节/段落/表行→原始参数/单位→外部手册/采购/预约条目`。阅读`environment/resources.yaml`并实际执行版本命令。安装位置`/skills/weekly-skill`，引用资源只用其下相对路径`references/feasibility-schema.md`、`scripts/feasibility_audit.py`。
4. 尽早保存制度合规的部分`result.json`；中间证据表和计算放`/app/work`，实际正式结果及合同允许附件放`/app/output`。缺页、附件不可读、工具失败分别记录已审和未审范围。

## 七域审查与版本复审

1. 实际三个候选版本分别建包，不跨版借用参数、资源、风险或结论。先列版本差异，审安全、伦理、设备能力、样本和时间硬约束，再完整审其余条目；硬阻塞不妨碍给出其他域部分审查。
2. 七域均逐条写“对象(版本+原文定位)—来源定位—判断—行动”：
   - 假设与变量：可检验性，变量操作定义、单位、范围、测量与目标匹配。
   - 对照组：本案必要对照与混杂控制；不把非必要对照强加为硬门槛。
   - 设备材料：型号、量程、精度、附件、规格逐项核验，资源仅用“已具备、可外协、需采购、不具备”；不能归类时写“信息不足、待核验”，不默认具备。采购/外协另核货期、预算及前置依赖。
   - 时间成本：人工、占机、等待、准备、检测周转、货期与预约；逐数复算，缺价/缺时不按0。
   - 参数范围：原值、单位、有限域、上下限、步进、容差、互斥与来源；未写≠合规，越界指出冲突双方。
   - 风险与异常：触发、证据、降级、替代、止损和转人工；“注意安全”不算处置。
   - 伦理与安全：按实际触发事物核对任务明示层级、材料、状态、周期；缺证据只列待确认，不杜撰法规或已获批。
3. 样本用量按组数×重复×单样量×有来源损耗核对可用量和保存窗；成本逐行数量×单价，币种不混加；预约/外协/采购前置与依赖图决定时间窗，前瞻合同不解读为现实资源。
4. 判定按合同允许表达：硬阻塞给“不可行”及关键事实；缺信息给“无法判断”及补证对象；采用“有条件可行”时逐条含版本/条目、全部条件、责任角色、最晚解除步骤、验证方式及复审节点；一般优化与开工阻塞分开。
5. 替代设备、材料、外协路径重新做兼容、域、安全、伦理、成本和工期检查。标记`changed_domains`并保留旧判断→变化依据→新判断；任何版本改变都重跑受影响七域，不伪造真人签核。

## 确定性复核

按相对文件`references/feasibility-schema.md`构造合成的工作输入，运行：

```bash
python3 /skills/weekly-skill/scripts/feasibility_audit.py --input /app/work/feasibility-audit.json --output /app/work/feasibility-audit-result.json
```

仅用Python标准库；检查三版、七域覆盖、证据定位、资源状态、条件五要素，复算样本/成本/最早完成日并区分信息缺口和阻塞。退出0表示审查结构和算术完成（可以包括被正确判为不可行的版本），退出2表示审查本身未通过。输出是辅助证据，不得覆盖case结论枚举或自动将未写信息变通过。

## 结果与判读

在实际合同许可位置容纳：版本化七类审查、对象/资源状态/结论/完成条件；证据、复算、风险与替代路径；安全、伦理、设备、专家确认项。保留真实状态、来源、不确定性、版本差异与再审查记录。材料缺失、无法判断、运行失败分开记录。有条件但无角色/验证/复审节点时不得标完成。

仅合同要求时输出审查/复算附件及可编辑源文件；要求Office/图示时真实渲染PDF/PNG检查，无要求不机械制造图表。向JSON解析器核对正式字段、类型与附件，不增加顶层键。

## 最小非官方示例

虚构v1/v2/v3：`2组×3重复×5 mg×1.1=33 mg`，可用40 mg；预约第3日、采购第5日、执行2日、窗口第10日，则最早完成`max(3,5)+2=7日`。v2仅一项条件，写明负责人、步骤前节点、验证和复审。运行上条命令。示意输出（非正式案例结果）：样本余量7 mg、第7日、v2“有条件可行”；不是实际样本库存或真实预约结论。

## 恢复、依赖、维护与自查

输入缺页时保留其他域结果；单位/参数不明则`info_missing`；伦理未定或预算/时间冲突给具体补证或合法替代；工具异常保存错误、中间表和重跑命令。不能执行时仅离线审查，不把失败变通过。

本地实测Python 3.9.6（`/usr/bin/python3`），运行时用真实`python3 -V`记录，需Python 3.9+且无第三方依赖。单案预算64请求、900秒、每次响应16384 tokens（含推理）；平台3案例×每条件3重复，实际轨迹由平台记录，不捏造。

版本1.0.0；规则基线2026-11-18 manifest及`challenge-2e2c5820`快照（`ARMI:2611.000078v1`，SHA-256 `25153ad7709eba1a60aa12e49d737e13854557de50554cdc99b95e3c9780ff76`，`current_matches_saved=true`）；真实case/task优先。规则变化时记录差异、修订版本并重跑测试。
