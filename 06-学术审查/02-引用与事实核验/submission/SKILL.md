# 论断—引文语义核验

## 触发与目标
读取实际真实全文及其可得来源，把“出现过引用”转换为“哪个子论断由哪一版来源的哪句话支持”。不因题名相似、引用数量或缺失访问权限直接下结论；不得编造 DOI、快照、撤稿状态、文献主张或科学事实。

## 输入、契约与目录
1. 先完整读 `/input/case.json` 与 `/input/task.md`，原样提取真实 `case_id`、`output_contract`、目标 facet 和版本要求到 `/app/work`。真实字段名、结构、类型及枚举优先于本 Skill 内部术语；没有真实案例不能用示例代替。
2. 读取任务指定的**全部**摘要、方法、结果、讨论、图表、补充数据、参考文献，以及每个来源实际可得全文/摘要和元数据。建立稿件、来源版本、页码和可读范围清单；不沿用旧短摘录。
3. 读 `environment/resources.yaml`，实测文献全文、网页/数据库、PDF 渲染及 OCR 能力的版本、安装、权限与使用条件。只保存真实访问结果及实际本地路径，不虚构登录会话或数据库记录。
4. 解析中间件、论断对、数值表和查询日志放 `/app/work`；最终真实契约产物放 `/app/output`。

## 原子论断与四级支持
逐句拆分可独立核验的事实、比较、因果和数值子结论，保存 `claim_id`、说话者、对象、条件、方向、强度、限定词、引文标识和原句位置。一句多个子结论必须分别建对；作者自己的实验结果、引用转述和明示假设不能混同。

每一对判断：
- `full_support`：实际来源覆盖全部关键子结论，对象、条件、方向、强度一致，原文可定位。
- `partial_support`：只支持部分子结论，或对象/方法/时间范围较窄、需要降低强度；明确写出未覆盖部分。
- `unsupported`：已取得足够相关原文，明确错配或方向相反；**获取失败、找不到支持句、标题不一致本身都不是不支持**。
- `undetermined`：全文不可得、引文歧义、版本冲突未解决、来源上下文不足或权限受限；列待补材料及已真实尝试的路径。

保留“支持/反驳/仅背景”的角色和多来源共同支持关系。定位必须到稿件和来源的页、段、句、图表或数据条目；双方逐字摘录、来源版本和可得的稳定链接/实际快照路径一并保存。

## 专属检查矩阵
以下每项均标 `passed/issues_found/review_required/not_checked` 与范围，并映射任务六类 facet：
- `claim_atomicity`：摘要、方法、结果、讨论全覆盖，拆分多个子论断并保留限定词与归属。
- `semantic_support`：逐项对象/条件/方向/强度与时间窗对齐，不能用关键词重合代替全文语义。
- `source_reliability_version`：真实核验出版类型、版本、预印本/正式版差异、更正和撤稿；查询失败写“未核实”，绝不反推“无撤稿”。
- `evidence_locatability`：双方页段图表/数据条目可回查，引用与来源一一对应；版本变化分别定位。
- `cross_section_numbers`：只在同一对象、指标、总体、时点、单位及统计口径下比较数值、方向、显著性。
- `related_facets`：因引文或事实链暴露的方法设计、统计报告、论证和规范线索；不借本题代做完整统计复算或投稿检查。

## 原句级发现、严重度和误报抑制
每条问题包含定位、逐字原文、类型、严重度与理由、双侧依据和可执行建议；例如明确需要删去哪个外推对象、把哪句因果降为相关、补哪一个版本或统一哪一处的单位/分母。`major` 用于核心论断失去/超越支持，`moderate` 用于重要局部子结论，`minor` 用于非核心修正，`advisory` 仅建议；不使用缺乏实际伤害证据的 `critical`。引用格式差异不得自动等同核心结论不受支持。

完整限定词、作者明确承认的短板、不同亚组/时点/分母、标准误与标准差、比例与百分比、预印本明确标版均是合理写法。预印本不自动低质量；仅摘要可支持摘要中实际可见主张，超出的部分仍未核实。版本冲突并列而非选择有利版本，证据不足降为待复核；支持矩阵允许零问题。

## 确定性比对工具
作者环境实测 `/usr/bin/python3` 为 Python 3.9.6；脚本仅依赖标准库 `argparse/decimal/json/pathlib/sys`，不联网、不需安装。将真实人工全文核验得到的结构化 `/app/work/claim_review.json` 运行：
```sh
python3 /skills/weekly-skill/scripts/check_claims.py /app/work/claim_review.json > /app/work/citation_validation.json
```
工具验证四级结论及来源证据的必要条件、稿件/来源原句唯一性、缺失来源只能 `undetermined`、覆盖范围一致；对已人工标注同一 `metric/population/time/unit/measure_kind` 的数值才用 `Decimal` 比较。输出 `numerical_consistency_candidates` 只是复核候选，不是自动缺陷。退出 0 为结构通过，2 为输入/证据校验失败。

## 输出、恢复与完成边界
尽早保存诚实的部分 `/app/output/result.json`，使用真实 `case_id` 和 `output_contract` **全部原字段**，不新增猜测字段。保留论断—证据表、原始输出、实际日志、版本、状态和不确定性，并区分通过/问题/待复核/未检查。辅助结果和最终 JSON 一致；仅实际生成 Office/slide/diagram 可编辑产物时附真实预览。

来源取不到时封存该对为 `undetermined`，继续其他对；数据库/网络权限失败记录真实尝试而非填结果。缺页或图表不可读只缩小相应范围，跨章数值检查不得宣称完成。原始数据不足时不做或捏造复算。引用歧义列候选来源待复核，恢复时从 `claim_id` 与版本台账续跑。规则更新以最新案例和契约为准，保留差异。

## 最小非官方示例
**示例/非正式核验（完全合成，不对应真实文献）**：稿件论断“K使成人所有场景结局改善30%[S1]”，S1 原文为“在体外成人来源细胞模型中，K使指标下降30%”。判 `partial_support`：细胞模型支持局部对象和方向，不支持“成人所有场景”和临床外推；定位双方段句，严重度按该论断是否为核心主张定，建议改为“在所述细胞模型中观察到指标下降30%”，不能改成虚构临床效果。若只有 S1 标题，判 `undetermined`，不是“不支持”。

## 自查维护
先按稿件所有引文检查是否都有论断对，再逐对回查双侧原文、版本、限定词、定位和判定；核对数值候选的分母/单位/时点后才能转为发现。重跑同一来源版本，记录静态抽取与判定差异。运行能力、来源或契约变化时更新检索记录及测试，重测四级支持、仅摘要、版本差异、数值口径和访问失败；不自建平台分数或金标准，不保存正式答案。无真实公开 GitHub 链接不创建 `GITHUB_URL.txt`，不上传、不发 PR、不提交。
