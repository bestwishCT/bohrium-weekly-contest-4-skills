# 方法—变量—模型—结果审查

## 适用与禁止
先理解研究问题和设计，不套用单一统计模板。不得把“未报告”升级为“做错了”，没有原始或充分汇总数据时不计算、不补造 p 值、CI、power 或临床意义。不替代审稿结论、投稿决定、全文翻译或语言润色。

## 启动真实案例
1. 完整读 `/input/case.json`、`/input/task.md` 和真实 `output_contract`，原样保存任务 facet、类型及枚举要求；本 Skill 内部分析字段不冒充官方字段。
2. 阅读任务给定的**完整**方法、结果、图表、附录、方案、数据字典和统计输出；建立文件版本、可读章节、变量与模型索引。不要只搜 p 值，不从标签预设缺陷。
3. 读取 `environment/resources.yaml`，实测 PDF/表格/图与计算工具的真实版本、路径、安装、来源和使用条件；不存在原始数据时明确不可复算。
4. 中间抽取、变量表、数值锚点、计算输入和日志放 `/app/work`，最终报告与可编辑产物放 `/app/output`。

## 五面专属检查矩阵
每行必须有状态 `passed/issues_found/review_required/not_checked`、范围、原文证据及理由；另建真实任务要求的六类 facet 映射：
1. **研究设计**：研究问题、假设、设计类型、分析对象、主要/次要终点；分组、对照、随机/盲法、偏倚控制；判断是设计不能支持结论、实施报告不足还是资料不足。
2. **变量定义**：暴露、结局、协变量和分组变量的测量、编码、单位、切点、缺失值及分析类型；比较方法/结果/图表口径，不能凭变量名猜连续或分类。
3. **统计方法**：独立性、重复测量、聚类、分布前提、模型变量类型、交互、竞争风险（如实际适用）、多重比较与敏感性分析；只有假设可验证时才判适配错误。
4. **样本量与效能**：目标/实际/分析样本流，效应量来源、alpha、把握度、估算公式、失访剔除及实际解释。不是所有探索性或精确估计研究都必须做事后 power。
5. **结果报告**：效应量、CI、精确 p、统计量、自由度、误差类型、单双侧及正文表图一致性；区分报告缺项、方向解释错误与可复算数值错误。

作者已明确报告的局限不得重复报为“未披露”；多种方法均可时列条件而非指定唯一正确方法。未做多重校正前确认同族假设，重复的生物学样本与技术重复不要混淆。

## 发现格式与严重度
所有发现包含真实原句/表号/单元格或图注定位、`type`、`severity` 和理由、`basis` 及可执行 `recommendation`：
- `reporting_omission`：定位到最近的方法/结果句并说明附近及附录的搜索范围，不声称证明作者未实施；
- `design_or_method_error`：必须有正面原句证据说明实际设计/实施与推断不相容；
- `calculation_or_reporting_inconsistency`：并列真实输入、公式、版本和双向位置；候选须人工核对模型与口径；
- `interpretation_overreach`：区分不显著与无效应、统计与实际意义、相关与因果。

`critical` 只用于有直接安全/伦理后果且证据充分，`major` 使核心推断失效或无法复现，`moderate` 影响重要结果解释，`minor` 为可局部修正报告问题，`advisory` 为可选增益。缺 CI 不自动等于计算错误，缺 power 说明也不自动等于样本不足。

## 确定性复算和误报抑制
作者环境实测 `/usr/bin/python3` 为 Python 3.9.6；资源只用标准库 `argparse/decimal/json/math/pathlib/sys`。将人工阅读全文后填好的 `/app/work/method_review.json` 执行：
```sh
python3 /skills/weekly-skill/scripts/check_methods.py /app/work/method_review.json > /app/work/method_validation.json
```
仅对明确标注为独立两组、效应量和标准误可得的记录复算 z=效应/SE、双侧正态 p=erfc(|z|/sqrt(2)) 及 95% Wald CI；按记录容差输出一致或复核候选，保留公式。对 `<`/`>` 界限只做包含关系核对。配对、重复测量、非独立或模型不明记录不强行用 Wald；任何输出都只是候选，需结合设计和四舍五入人工判断。脚本另检查五面覆盖、未报告/方法错误分型和原句定位。退出 0 为结构通过，2 为坏输入/证据校验错误，不输出回溯。

合理非常规设计、精确检验、置换/Bootstrap、贝叶斯区间、重复测量混合模型、预先说明的探索分析，以及 `p<0.001`、不同层级样本量均不得直接套正态 Wald 或报“未给精确值”硬伤。无对照不自动无价值，但结论须限于设计能力；非显著不等于无效应。

## 输出和异常恢复
按真实契约落 `/app/output/result.json`，含 `case_id` 和**全部原字段**，真实状态、来源、版本、不确定性与变更记录；变量表、计算、覆盖矩阵同 JSON 一致。尽早保存部分结果及证据，不能以空白填充未读部分。只有实际生成可编辑 Office/slide/diagram 时才提供真实 PDF/PNG 预览。

缺方法/变量/统计输出时标“未报告/无法判断”及所需材料。原始数据不足不做复算；图表失败不从 OCR 猜值；混杂语言或多版统计输出先保留原值和版本。截断或预算不足按五面保存恢复点，跨章结果核对未完成。工具异常继续可独立的项目，退出 2 后修正输入从已保存变量表恢复，不重跑外部查询。最新官方更新与真实契约优先。

## 最小非官方示例
**示例/非正式方法审查（完全合成）**：独立两组、方法中预设双侧 Wald，效应量 1.96、SE=1.00、稿件 p=0.21。复算 z=1.96，双侧正态 p≈0.049996，95%CI≈[0.000036,3.919964]；候选定位方法与结果句，建议先确认是否采用了另一模型/舍入口径，再更正 p 或补模型，不直接断言全文统计无效。若为配对设计或 SE 实为组内 SD，则停止该复算并标所需输入不足，不报计算错误。

## 自查与维护
逐项从变量表查模型与输出，再从计算候选回查设计、样本独立性、单位和统计口径。检查五面和六类 facet 状态、发现类型、严重度理由、实际定位及建议；零缺陷允许。保存真实重跑版本与数值输入，确认同输入结果可重跑。统计库、公式或契约变化时更新实现并用合理替代方法及不可复算反例回归，不编官方增益。无真实公开 GitHub 链接不创建 `GITHUB_URL.txt`，不上传、不发 PR、不提交。
