# 证据绑定学术合规检查

## 范围与克制
只在真实任务指定的国家、机构、期刊、附件和授权范围内检查。风格差异、相似性或遗漏声明不自动等于不端、无许可或无审批；不得编造法规、指南、许可证、批件或元数据。不做法务/伦理正式决定，不重新分析数据或代投稿。

## 材料与真实契约
1. 先完整读 `/input/case.json`、`/input/task.md` 与真实 `output_contract`，记录指定 facet、适用规范和字段；不把本模板的六面或内部字段硬塞进未公开契约。
2. 按任务权限读取**实际完整**稿件、附件、数据/代码声明、署名贡献、伦理/知情同意、授权许可、参考文献、第三方素材及目标指南。逐页建立可读、缺失、受限和版本清单，不沿用旧摘录。
3. 读 `environment/resources.yaml`，实测全文、图片/表格、参考文献及官方指南访问/解析工具的版本、路径、来源和权限。规范依据必须来自真实获取内容，记录条款原句、文件/URL、版本或发布日期、真实访问日期和适用条件；本 Skill 不内置凭记忆编写的法律条款库。
4. `/app/work` 保存条款映射、证据台账和日志，`/app/output` 保存最终真实契约产物。敏感或受限内容禁止未授权外传，报告只保留必要定位、风险摘要及安全哈希，不复制无关敏感值或公开语料。

## 六类专属风险矩阵
每行标 `passed/issues_found/review_required/not_checked/not_applicable`、范围、材料 ID、依据 ID 和理由；按任务旁注事实、方法统计与论证线索但不越界代审：
- `integrity_and_authorship`：数据/图像明确复用、重复发表线索、贡献与署名、利益冲突、致谢/基金一致性；只有线索时写风险及待补佐证。
- `citation_integrity`：真实来源、元数据、论断支持与指定风格一致性；风格和标点只在实际适用指南下检查，不等同造假。
- `privacy_and_data`：直接标识符、潜在再识别组合、受限/未公开数据、伦理授权及可用性声明一致性；建议最小化、脱敏或限制披露。
- `copyright_and_license`：第三方图片、表格、代码、数据的来源、实际许可及署名/相同方式共享等条件逐项核对；不明就是不明，不猜公有领域或可商用。
- `research_ethics`：涉及人的同意和审批范围、批件报告、动物研究依据、风险获益与设计一致性；缺编号可判报告缺失，不推断未审批。
- `target_submission_rules`：将真实目标指南拆条映射稿件缺失、超限和格式冲突；多版本不混用，未指定目标时不杜撰字数或声明要求。

## 风险发现与严重度
每条发现给真实定位（必要非敏感原句）、风险类型、`certainty`、严重度与理由、适用条款/授权原句及版本、可执行整改。分类为：
- `confirmed_noncompliance`：适用规定明确且材料事实可直接证明不符；
- `risk_signal`：高风险线索，但缺授权/元数据/外部事实，只待复核；
- `reporting_gap`：明确报告范围内未找到声明/编号/来源，最近原句作定位并写检索范围；
- `procedural_suggestion`：不影响合规成立的可选改进。

`critical` 仅实际敏感泄露或迫近安全损害且证据明确；`major` 可能阻断发表或动摇重要许可/伦理依据；`moderate` 重要材料缺项可在发表前整改；`minor` 非实质一致性；`advisory` 风格或可选改进。参考文献标点不得与敏感信息暴露同级。整改明确补哪份声明/授权、脱敏哪个位置、替换哪个素材、核对哪条指南或修正哪个引用，不泛写“注意合规”。

## 误报抑制与确定性台账校验
回读上下文排除已授权、适用于其他研究类型、合理学科惯例、作者主动限定及不同分析/发表版本。指南不适用不生成违规；依据不可用、外网不可用或许可不明均待复核。缺声明不代表未实施，相似表述不证明抄袭或重复发表。合法零发现允许。

作者环境实测 `/usr/bin/python3` 为 Python 3.9.6；脚本仅依赖标准库 `argparse/hashlib/json/pathlib/sys`，不联网。将真实审查的 `/app/work/compliance_review.json` 运行：
```sh
python3 /skills/weekly-skill/scripts/check_compliance.py /app/work/compliance_review.json > /app/work/compliance_validation.json
```
校验者检查六面状态、规则/材料引用、适用版本、原句唯一性和严重度/建议，确保确定违规有已获得的适用条款，而依据未核实不能判确定违规。敏感原句用 SHA-256 与定位代替，不在标准输出复述。它不用关键词判不端或许可，不自动制造候选。退出 0 为台账结构通过，2 为输入或证据错误；不输出回溯。

## 输出与隐私安全恢复
按真实契约尽早保存部分 `/app/output/result.json`，含 `case_id` 与**全部原字段**，保留输入、实际状态、来源、版本、不确定性和真实变更记录。依据台账与最终 JSON 一致，区分不符合、风险线索、报告缺失、通过、待复核与未检查。可编辑 Office/slide/diagram 只有实际生成时才出真实且已脱敏 PDF/PNG 预览；运行期二进制保留但不得公开。

依据或指南不可得则记录真实访问失败、标待复核/未检查，继续可独立项；受限材料停止未授权处理和上传。缺页/OCR失败不猜图像/批件，保存最后完整的材料—规则映射供恢复。法律或伦理适用不明时转主管机构复核。敏感错误日志也不得回显敏感值。最新规则、实际指南与契约优先，不可伪造快照。

## 最小非官方示例
**示例/非正式合规审查（完全合成材料与合成指南，不是真实法律意见）**：图注“图2转载自示例工作室”，附件仅署名而无许可，所指定合成指南明确“第三方图片须列许可”。定位图注与该指南原句，类型 `reporting_gap`，依实际阻断影响定严重度，建议“向权利方确认适用范围；补具体许可/授权，或替换为许可清楚素材”，不得写“已侵权”。若附件已有 CC BY 4.0 许可且满足署名或其他风格未指定，不制造问题。

## 自查与维护
先逐材料核有效依据与适用范围，再逐条款查稿件，并逐发现回查原句、授权差异、版本和敏感最小化；核对待复核不得变确定结论、通过范围与未读附件。重跑比较判定、定位和严重度并记录。指南/法律或许可变化时仅更新真实来源版本，重跑不适用指南、已有授权、缺编号、许可不明、隐私脱敏和截断反例；不宣称法律准确率或官方分数。无真实公开 GitHub 链接不创建 `GITHUB_URL.txt`，不上传、不发 PR、不提交。
