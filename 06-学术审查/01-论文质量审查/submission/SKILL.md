# 分面论文质量审查

## 触发与边界
先读取真实任务，再审查实际稿件；不得依据题目、领域标签或既有短摘录预设有缺陷。以“少而可核”的发现替代总体评语，不凑数量。本文档的程序步骤是内部工作流，运行期字段名、枚举、层级和必填性只服从真实 `output_contract`。

## 真实调用和材料
1. 完整读取 `/input/case.json`、`/input/task.md`，逐字保存真实 `case_id`、`output_contract` 及 facet 到 `/app/work/runtime_contract.json`；没有真实案例时停止正式作答，不用本 Skill 的示例结构冒充官方结构。
2. 盘点任务指定的完整 PDF/文本、正文、附录、图表、补充材料、参考文献及目标指南。读取原文全部页，而非只读摘要或搜索片段；记录稿件标识、实际路径、页数、可读章节、文件哈希及版本。
3. 读取 `environment/resources.yaml`，以能力清单及 `--version` 实测为准调用文本抽取、PDF 渲染、OCR 与图表工具。保留真实命令、版本、来源、权限和失败信息；未提供的能力不得声称可用。
4. 在 `/app/work` 保存全文抽取、页段索引、数值对照、覆盖矩阵、`review.json`、工具日志及恢复点；在 `/app/output` 保存真实契约要求的最终文件。

## 七行专属检查矩阵
为每行设置 `passed/issues_found/review_required/not_checked`、实际范围、证据 ID、理由；同时按任务映射其六类 facet。没有适用材料写不适用理由，不要自动写通过。
- `overall_structure`：章节功能与层级、摘要对应、引言问题到结果/结论的交付，防止形式齐全而内容未交付。
- `fact_consistency`：跨摘要、正文、图表、附录核对数值、样本量、单位、定义；区分总体/亚组、基线/随访、绝对值/变化值。
- `citation_support`：本文原子论断与被引原句的对象、条件、方向、强度和版本；缺被引原文只待复核。
- `methods_design`：研究问题、抽样/对照、指标、重复、随机化、偏倚控制是否匹配；实施可接受但描述不足另列报告缺失。
- `statistics_report`：样本流、效应量、区间、精确概率、误差含义及表正文一致性；缺数据不复算。
- `argumentation`：前提—证据—限定—结论，检查相关/因果、外推、反证及作者明示假设。
- `scholarly_norms`：仅按真实目标要求与材料检查数据/代码、伦理、利益冲突、图表来源许可；不杜撰期刊门槛。

先纵向完成每行已读范围，再横向核对跨章承诺和数值。对每条候选回读前后至少一段及所指图表/来源，区分“事实错误、证据不足、规范问题、建议性意见”，并区分设计缺陷与报告不全。

## 原句级发现与优先级
每条发现至少含内部字段：
- `id`、对应 `facet`、`location`（文件名、页/节/段/句或表图/单元格）、逐字 `quote`；
- `type` 与实际 `severity`，`severity_reason` 明写主结论、数据可信度、可复现性及局部修正影响；
- `basis` 说明可核事实或适用依据，`evidence` 保存双方原句和定位；不要只写领域常识；
- `recommendation` 具体到核对哪个数、补哪段/哪个声明、补什么证据或将哪句限定到何种范围；
- `certainty=confirmed/needs_review`，事实不充分时降为待复核而非硬判。

严重度锚点：`critical` 为可直接伤害或有明确合规阻断且证据充分；`major` 动摇核心结论或关键可复现性；`moderate` 影响重要局部结论或解释；`minor` 可局部修正且不改主结论；`advisory` 仅改进建议。没有伤害或投稿阻断证据不用 `critical`，同一缺陷不假装统一等级。

## 误报抑制
- 研究方案尚无结果、探索性分析、负结果、作者自选命名及非常规章节均可在适用范围内合理；先看书名页/任务/作者说明。
- 明示假设、引用他人观点、合理局限、不同分母/亚组/时点、绝对变化与相对变化不是自相矛盾。
- 缺某项声明先确认任务和研究是否要求；不规范的偏好只作低级别建议。不能确认的候选删除或移入待复核。
- 零发现是合法结果，已通过行也保留覆盖范围与核对证据。

## 确定性校验器
作者环境实测 `/usr/bin/python3` 为 Python 3.9.6；本资源只用 Python 标准库 `argparse/json/pathlib/sys`，无需安装或联网。将真实审查整理为本文件和脚本所示的 `/app/work/review.json` 后运行：
```sh
python3 /skills/weekly-skill/scripts/check_review.py /app/work/review.json > /app/work/quality_validation.json
```
脚本检查七行矩阵、非全文范围、必填发现字段、原句与双方证据是否唯一可回查及 facet/发现引用一致。它不做语义判分、不推断缺失结果或数字错误，输出候选数始终为空，不能替代 Agent 全文审查。退出 0 表示结构校验通过，2 表示 JSON、字段、引文定位或范围错误；无回溯输出。资源只以 `/skills/weekly-skill` 安装路径调用，不依赖作者机器路径。

## 输出与异常恢复
尽早按真实契约写 `/app/output/result.json` 的诚实部分稿，包含 `case_id` 及**全部原字段**，不添加提示词臆造字段。覆盖通过、发现、待复核与未检查范围，保存输入标识、状态、来源、不确定性及真实变更记录；辅助矩阵与最终 JSON 一致。仅当实际生成可编辑 Office/slide/diagram 时才做真实 PDF/PNG 预览。

PDF 解析失败先重试可用文本层，再按真实工具渲染/OCR；图表仍不可读则相关行未检查。缺页、截断或预算不足时封存已读页段及发现，跨章行保持未完成并写恢复点；保留二进制与解析结果。参考文献缺失只影响引用完成度，不臆造不支持。数值与结论冲突并列双方位置，需原始数据才能确定的列为待复核。规则或契约更新时以最新输入覆盖内部模板并记录差异。

## 最小非官方示例
**示例/非正式审查（完全合成）**：稿件结果段写“共42人完成”，表1同口径行写“完成，n=41”。内部发现定位为 `Results, P2` 与 `Table 1, completed row`，摘录双方原句，类型 `internal_inconsistency`，严重度 `moderate` 且理由为“影响样本流但不自动否定效应估计”，依据为两处原句，建议“回查锁定样本流，统一两处并说明排除1人的追踪位置”。若表1明确是“纳入主要分析者”而正文是“完成随访者”，则不是缺陷，不报此条目。

## 自查与维护
交付前逐条从原稿复制粘贴核对双向证据，再从矩阵查漏；检查定位唯一性、严重度理由、建议可执行性、实际覆盖与契约全字段。重跑同一输入比较定位/判定差异并记录。学科口径或工具版本变化时先更新矩阵和合成反例，再重测正常、惯例写法、不可读图表、截断及重跑；不保存预制正式答案、官方分数或虚构轨迹。无真实公开 GitHub 链接时不创建 `GITHUB_URL.txt`，不上传、不发 PR、不提交。
