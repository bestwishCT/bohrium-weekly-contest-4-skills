# 六维论文结构与论证诊断

## 触发与交付边界
当用户给出六维诊断、定位化编辑动作、相似候选人工复核状态相关材料或明确要求“对完整学术论文开展研究问题、章节结构、论证链、段落关系、重复内容和结论边界六维源文定位诊断，给出可执行编辑动作”时使用。核心交付：**可编辑JSON/Markdown诊断与编辑计划；六维均记录“发现问题/未发现/无法判断”，不强找缺陷。**

不得把提纲、原则、评分自述或审计表当作任务成品；按真实契约交付完整、可编辑结果。纯内容问答、事实检索或超出明确支持范围的任务不要擅自套用本技能。

## 专属工作流
1. 给章节、段落、句子稳定ID和可检索原文锚点；识别实际稿型与研究问题，不以IMRaD或其他学科惯例强套缺陷。
2. 跟踪研究问题/贡献在方法、结果、结论的响应，章节卡写“功能—输入证据—输出结论—与下章关系”；具体动作指出前移/后移/合并/拆分的位置。
3. 拆出论点—数据/实验/文献/推理映射，区分断链、跳跃、循环、证据不足和文风问题；不从关键词相似度直接推出逻辑错误。
4. 核查段间过渡及跨章同义重复。相似候选必须语义复核是否各负其责，给移动目标、合并对象、拆分点和过渡内容，不主动重写全篇。
5. 将摘要/结论的范围、比较、因果和普遍性与实际样本/条件逼近，指出需收窄的原句、建议边界和证据；限制不机械套话。
6. 每条诊断含定位、六维类别、原文事实依据、影响、动作、受影响章节、复核方法、优先级和决策点。内部审计动作字段对应为 `anchor`、`excerpt`、`rationale`、`action`、`verify`、`impact`、`affected_sections`、`priority`、`decision_point`；文本字段须为非空字符串，`affected_sections` 须为至少含一个非空字符串的数组。优先级枚举仅在原case明确规定时采用，不自行增设公开合同约束。六维分别写checked状态；无问题就如实无问题。
7. 最终交付编辑计划而非未经请求的新稿；默认JSON/Markdown即可，PDF和Office仅在更新case实际要求时生成。

## 真实运行入口与资源
- 先完整读取 `/input/case.json` 与 `/input/task.md`，再读取 case 指向的全部实际材料；执行前也读取 `environment/resources.yaml`。以原始 `case_id`、章节范围、语言、格式和 `output_contract` 为唯一契约，Unknown 不猜测，未要求的附件不制造。
- 平台把本技能安装到 `/skills/weekly-skill`。以技能根目录为基准使用 `scripts/audit.py` 和 `references/record-template.json`；例如 `python3 /skills/weekly-skill/scripts/audit.py /app/work/audit_input.json`。模板只是内部审计结构示意，不是答案或公开 `output_contract`。
- 读取实际case后先运行 `python3 /skills/weekly-skill/scripts/initialize_case.py`（默认读取 `/input/case.json`、`/input/task.md`，写入 `/app/work` 和 `/app/output`）。驱动只编目显式 `materials` 路径及可选 `--material` 路径，保留真实 `case_id` 和原始 `output_contract` 字段并先落 `partial`；未支持的case材料布局须由Agent实读后显式传入，不得猜测。对声明的UTF-8 `.md/.txt/.text/.tex` 材料另生成 `/app/work/manuscript-index.json`，含章节、段落稳定ID、精确字符区间和待复核的句子候选；索引不是语义诊断，PDF/其他格式仍须用实际工具抽取后再定位。驱动不生成六维诊断，返回partial不代表论文分析完成。
- `/app/work` 保存只读输入快照清单、抽取文本、稳定ID、分块状态、审计输入/输出与中间稿；`/app/output` 只保存契约要求的完整可编辑成品、指定预览和 `result.json`。制作目录是 `/app/submission`，不要污染输入。
- `result.json` 必须原样保留 `case_id` 和实际 `output_contract` 的全部原始字段，把成品、来源、状态、不确定性、变更、缺口落到契约指定字段；不得把示意字段强加给 case。内部审计字段留在 `/app/work/audit_input.json`，须按实际字段语义逐项映射到公开契约，不能把 `dimensions`、`actions` 或四个新增诊断字段自动复制为公开字段。各状态枚举以契约为准；初始化驱动只填写契约允许的部分状态与缺口，其余未知值留空，等待Agent完成。成品落盘后运行 `python3 /skills/weekly-skill/scripts/initialize_case.py --finalize`，递归检查原 `case_id` 及嵌套 `required/type/enum/items`，报告写入 `/app/work/finalization.json`；校验失败退出2并在状态枚举允许时标为 `partial`，不得为通过校验杜撰缺失值。
- 材料编目至少记录材料ID、真实路径、类型、版本线索、可读范围、缺失及定位方式；证据映射记录成品锚点、论断/对象、来源ID、精确位置、原文或数值、支持范围和处理动作。冲突双列，不静默择一。

## 增量执行、状态与异常
按64次请求、900秒和单响应16384 tokens预算分块：先落盘材料索引与审计台账，再完成全部可核实正文，随后替换局部文本、分块重建，最后运行确定性审计。长文使用稳定ID和术语/参数状态，不能循环通读全文。
- 状态区分材料缺失、科学/语义无法判断、工具或权限失败、部分完成；先保存诚实的部分成品和真实日志，能修JSON就修JSON，不删除已生成的真实产物。未执行的操作写未执行，不写成成功。
- 只有 case 明确要求且工具实际存在时才制作 Office/LaTeX 二进制或其真实 PDF/PNG 预览；保留可编辑源，逐件打开核查。纯文本/Markdown任务不主动增加预览。缺编译器、字体或渲染器时明确标记 blocked，不伪造二进制。
- 审计在 `/app/work` 生成独立审计输入，避免把测试数据混入正式输出；失败项回到具体源位置修复并重跑。禁止捏造实验、文献、DOI、人员、工具版本、分数、效率、白板或平台轨迹。

## 最小非官方示意与验收
以下仅为虚构“示意”，不是官方案例：将一段含“12 samples, p=0.04, Fig. 1 [A]”的短材料写入 `/app/work/audit_input.json`，执行上述 `audit.py`。应得到机器可读检查项；示例文本不进入 `/app/output`。实际案例必须替换为真实材料并产出契约指定的完整结果。
- 自查：核对所有契约字段和任务动作、抽样重读源/成品双向映射、搜索空产物与占位语、运行脚本并处理失败、在全新相对路径下复跑。结果必须可继续编辑，审计表/建议不能替代合约要求的成品。
- 维护：扩学科或格式时先加独立合成fixture，不改写旧断言掩盖错误；脚本只断言可机械验证项，语义判断仍由Agent逐条回读。来源为用户给定材料；无外部词表已捆绑。
- 依赖：核心脚本仅 Python 3 标准库，开发机实测 CPython **3.9.6**；运行时重新执行 `python3 --version` 并如实记录。任何可选外部工具都先探测，未探测不声称可用。
