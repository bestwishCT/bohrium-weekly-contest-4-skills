# 数值与论断双溯源的结果与讨论写作

## 何时使用与交付边界
用于把已有数据表、图、图注、统计输出、补充材料和真实文献写成“结果”“讨论”，或回查已有双章。核心成品是符合实际 case 的完整可编辑章节，而不是图表观察笔记、重绘建议、提纲、评分自述或审计表。结果陈述观察，讨论承担解释、文献对照和局限。

不得根据文件名、错误学科标签或视觉猜测补造数值、样本量、误差棒含义、统计量、P值、文献或实验。图上估读不得伪装精确表值，不显著不等于“证明无效”，单组前后变化不等于组间差异。机械脚本不能证明读图和统计解释正确，仍须逐项回读实际材料。

## 实际运行顺序

### 1. 保留真实输入和原契约，先落盘 partial
先读 `/input/case.json`、`/input/task.md`、`environment/resources.yaml` 以及 case 指向的实际数据表、图像、图注、统计输出、补充材料和文献，立即执行：

```bash
python3 /skills/weekly-skill/scripts/contract.py init \
  --case /input/case.json --task /input/task.md \
  --work-dir /app/work --output-dir /app/output
```

工具只读取 case 显式 `materials` 中的 `path/file_path/source_path`；实读后发现的补充材料用可重复的 `--material 真实路径` 加入，不猜目录。它记录真实路径、可读性、大小和 SHA-256，先在 `/app/output/result.json` 写诚实 partial。材料缺失、科学含义无法判断、解析/权限失败分别记录，不用“运行成功”掩盖未完成章节。

真实 `case_id` 和原 `output_contract` 只从当前 case 获取。原对象（含嵌套 `properties/required/type/enum/items`）逐字保存至 `/app/work/input_snapshot.json`；公开 result 仅填 `case_id` 和原合同声明的字段，内部审计字段留在 work。嵌套 required 递归生成类型占位；未知数字/布尔值或无安全 partial 枚举时保持 null/空值并说明，不任选枚举、不默认 0/false。不能为通过校验改写合同或状态枚举。

### 2. 建读数、统计与发现台账
在 `/app/work` 登记真实材料并保存抽取/核对记录：
1. **图表身份**：图/表/补充材料编号、面板、坐标、单位、图注和实际位置。区分 `data_table/plot/caption`，多面板与补充编号不可混用。
2. **读数**：保存实际值、有效数字、单位、来源位置及 `exact/estimated`。只有材料明确给出才记录 SD/SE/CI、样本量等；单位换算须有明示规则、保留原值与可复算过程。模糊图记录估读不确定性及“约/估计”，不输出伪精确小数。
3. **统计**：显著性绑定具体组别/条件比较、真实统计输出位置、P值和材料给出的阈值；材料未给自由度或检验名就留空。不能用数值大小自行猜显著性。
4. **发现**：按 case 图序或研究问题组织主要、次要、阴性和不一致结果；每条绑定读数及统计（若声称显著性），写明条件、方向、幅度和边界。所有已抽取读数都进入发现，避免选择性报告；没有阴性发现须回读确认而非补造。
5. **冲突**：原始数据、图、图注和统计输出不一致时并列记录位置与受影响正文；无 case 明示兼容规则不得挑“更合理”的值。

内部字段见 `references/record-template.json`（仅为合成结构示意，不是公开合同）。

### 3. 先结果、后讨论，保持论证分工
- **结果段**只写实际观察、组间/条件比较与统计结果，按 case 顺序覆盖所有相关图表；准确表达“趋势一致但未达显著”“仅在某条件出现”，不把机制解释混入结果。每个数值及图号/面板与台账一致。
- **讨论段**逐条绑定本研究发现或真实文献定位，解释一致、不一致及可能原因；说明引用与论断的关系，不能只堆引用。机制用“可能/推测”等与实际证据相符的措辞，不一致文献不得隐藏。
- 依据真实设计区分相关、预测与因果；观察性设计不写“导致/证明”，任何设计都不把有限结果写成普遍证明。局限具体到方法、样本、测量、统计及对结论适用范围的影响，避免泛泛自我评价。
- 找不到讨论文献、缺图/统计、单位不明或坐标不清时收窄论断并 partial，保留其他可核实章节，不用训练记忆补文献或插值猜图。

### 4. 审计真实双章并递归检查交付合同
```bash
python3 /skills/weekly-skill/scripts/audit.py /app/work/audit_input.json
python3 /skills/weekly-skill/scripts/contract.py check \
  --case /input/case.json --result /app/output/result.json \
  --snapshot /app/work/input_snapshot.json
```

`audit.py` 检查真实章节、数值标签与实际读数、精确值/单位一致性、估读限定、统计显著性来源、发现覆盖、讨论来源及位置、不一致文献、具体局限和因果边界。确定错误返回 `fail`，缺图/统计、估读不确定、未知设计、未核阴性或局限缺失返回 `partial`，两者均非零；只有完整机械审计通过才是 `pass`。`contract.py check` 保留真实 case_id 并递归检查原合同顶层字段、嵌套 required/type/enum/items；partial 或失败均非零。失败后修具体材料/正文并重跑，不能删检查或伪造统计让输出通过。

最终章节、真实来源/修改差异、不确定性、缺口和状态按原合同落 `/app/output`；读数与审计留 `/app/work`。不机械新增绘图或无关读论文步骤；仅 case 明确要求时生成 Office 等附件及真实 PDF/PNG 预览，工具不可用写 blocked/partial。

## 预算、可移植性与异常
- 预算：64 次模型请求、900 秒、每响应含推理 16384 tokens。优先 partial、材料清单、读数/统计台账，再分节起草和局部核对，不反复通读全文，不耗费预算重绘。
- 脚本只依赖 Python 3 标准库，通过 `/skills/weekly-skill` 相对资源运行，无个人文件、未声明服务或网络依赖。运行时记录实际 Python 版本，不虚构平台运行。
- 材料过大时按图表分块并保留稳定 ID；解析或权限失败保留已核成稿和真实错误。未执行的重算、检索、渲染写未执行。
- 禁止捏造实验、文献、统计过程、运行轨迹、对照白板、效率或分数；只有同输入、权限和预算的真实对照才能报告增益。

## 最小合成示意与维护
**以下仅为非官方合成示意，不是正式案例或预写答案。** 构造含一个精确表值、一个真实统计记录、一个阴性和一个不一致发现的 `audit_input.json`，先写读数/统计，再把发现原句写进结果、讨论论断和具体局限写进讨论；运行 `audit.py`。把 `significant` 改 true 而不给统计源，应得到 `significance_source` 失败。示意不得进入 `/app/output`；正式案例必须完整实读并执行 init、双章写作、审计与合同检查。

扩展学科或图表类型时新增独立合成回归，不改旧断言迁就错误。脚本无法自动判断估读是否忠实、机制是否合理或讨论是否穷尽文献，这些必须由 Agent/人工回读原始证据；相应不足保持 partial。
